## 1. 클라이언트 · 세계관

- **클라이언트:** **결(gyeol)**. 지금 기분을 색으로 고르면 그 색에 맞는 음악을 이어 주는 무드 기반 음악 스트리밍 앱이다. 운영사는 (가상) **주식회사 결사운드**다.
- **이번 장면:** 결 3.0 런칭 키노트 〈소리의 색〉. 3.0의 핵심 기능은 **무드 메쉬**다. 재생 중인 곡의 템포·조성·음색을 4개의 색 제어점으로 바꿔 앨범 아트와 앱 배경을 실시간 메쉬 그라디언트로 그린다.
- **스타일의 원래 맥락:** 메쉬 그라디언트는 2017~2021년 Stripe 홈의 WebGL 메쉬, iOS·macOS 기본 배경화면, Spotify 연말 결산(Wrapped), Figma Config 무대 그래픽에서 굳어진 "런칭 무대의 언어"다. 원래 무대(키노트 슬라이드)와 개인화 결산(Wrapped)이라는 맥락에서 출발한다. 그래서 index는 키노트 덱, profile은 결산 스토리, dashboard는 런칭 당일 관제 콘솔이 된다.
- **왜 이 클라이언트인가:** 그라디언트가 장식이 아니라 데이터가 되는 몇 안 되는 제품군이다. 곡마다 메쉬가 다르므로 "왜 여기에 그라디언트가 있나"에 늘 답이 있다. 커버 이미지 파일을 쓸 수 없다는 제약(브리프 5절)도 메쉬 커버 아트로 자연스럽게 해결된다.
- **감정 톤 (한 문장):** 객석 조명이 꺼지고 첫 소절과 함께 화면이 색으로 번지는 순간의 숨죽인 설렘. 크고, 조용하고, 한 번에 하나씩.

## 6. 레이아웃 문법 — "무대 프레임"

1. **장면 = 16:9 무대.** 데스크톱 장면은 `min-height: 100svh`, 안쪽 세이프 에어리어 `padding: clamp(24px, 5vw, 72px)`. 1440 기준 콘텐츠 폭은 1296px, 12단 그리드, 거터 24px.
2. **앵커 5종을 돌려 쓴다.** 장면의 주 메시지는 `좌하단 · 중앙 · 좌상단 · 우측 2/3 · 풀블리드` 중 하나에 고정하고, **연속한 두 장면이 같은 앵커를 쓰지 않는다.** 가운데정렬 섹션 헤더는 금지다. 중앙 앵커는 "한 문장 장면"에만 쓴다.
3. **무대 크롬은 고정 위치.** 좌하단에는 챕터명(한글, 14px, 자간 0), 우하단에는 카운터(`07 / 12`, Azeret Mono 12px), 하단에는 진행선(시그니처 2)을 둔다. 섹션 제목 블록이 따로 없으므로 무대 크롬이 그 자리를 대신한다.
4. **면의 교대.** 메쉬 무대 → 잉크 단색(#16131F/#0A0910) → 바탕(#F4F2F7) 순으로 장면 배경을 바꿔 리듬을 만든다. 같은 바탕 장면이 3개 이상 이어지지 않는다.
5. **작은 글은 플레이트 위에.** 메쉬 위에 직접 놓는 것은 `--t-statement` 이상 크기뿐이다. 14px 이하는 반드시 단색 플레이트(surface, 반경 16px, 패딩 12px 16px) 위에 둔다.
6. **정보 화면(pages)은 무대 밖.** dashboard·inbox·kanban·settings의 데이터 영역은 단색 `--bg`/`--surface`에 둔다. 페이지 상단 "무대 띠"(높이 220–320px 메쉬 밴드) 하나에만 메쉬를 쓰고, 그 아래로는 메쉬를 깔지 않는다.
7. **여백.** 장면 사이 간격은 0(장면 자체가 화면)이고 장면 내부 여백은 넉넉하게: 메시지와 보조 요소 사이 최소 64px(데스크톱) / 40px(모바일). 정보 페이지는 8px 그리드, 패널 간 24px.
8. **반경 체계(의도적으로 다르게):** 무대 장면 0(풀블리드) / 패널 24px / 커버 아트 12px / 입력 14px / 버튼·칩·탭 999px(필) / 배지 6px. "전부 같은 반경"을 피한다.
9. **그림자:** 기본 0. 깊이는 면 대비로 낸다. 오버레이(모달·드로어·팝오버·토스트)만 `0 24px 64px rgba(10, 9, 16, .28)`, 다크에서는 `0 0 0 1px #2C2839, 0 24px 64px rgba(0,0,0,.6)`.
10. **모바일(≤ 640px):** 타이틀 장면만 100svh이고 나머지는 자동 높이에 상하 72px. 세이프 에어리어 좌우 20px(최소 16px). 우측 2/3 앵커는 위아래로 쌓고, 카운터는 우상단으로 옮긴다.

## 7. 시그니처

### 시그니처 1 — 무드 메쉬 (4개 제어점 + 핸들 노출)
- 메쉬는 `--m1…--m4`(색)과 `--p1x/--p1y…--p4x/--p4y`(위치) 8개 변수로 만든 4개 radial-gradient 레이어다(`@property`로 색·위치 등록 → 보간 가능). blur와 블렌드 모드는 쓰지 않는다.
- **흐릿한 얼룩과 구별되는 장치:** 무대 장면과 index 컬러 장면에서는 제어점 위치에 **핸들**(지름 14px 원, 2px 흰 테두리 + 1px 잉크 외곽)과 라벨 플레이트(`P1 #FF4D2E`, mono)를 드러낸다. Figma 메쉬 편집기처럼 "설계된 메쉬"로 읽히게 한다. 포인터를 대면 가장 가까운 제어점이 최대 ±6% 따라온다.
- `[data-mood="001|014|037|062|090"]`를 body나 장면에 걸면 무드가 통째로 바뀐다. 팔레트 선택이 곧 테마 시연이 된다.
- **컴포넌트 전반 적용:** 곡·플레이리스트·알림 발신자의 썸네일은 전부 무드 메쉬 커버 아트(12px 반경, 핸들 없음)다. 아바타도 이니셜 + 그 사람의 무드 메쉬다. 진행바·슬라이더 채움, 활성 탭 밑줄, 차트 강조 시리즈, 스켈레톤 시머의 색은 현재 무드의 P1→P3를 따른다.

### 시그니처 2 — 클리커 진행선 + 카운터
- 키노트 리모컨의 "다음 장면" 감각을 3px 진행선(현재 무드 P1→P3 선형)과 `03 / 12` 모노 카운터 쌍으로 표현한다.
- **적용처:** index 하단 고정 진행선(스크롤 진행), navbar 하단 3px, 캐러셀(`2 / 5` + 선), steps(완료 구간 진행선), pagination(`4 / 18` 카운터 + 이전/다음 필), progress(본체가 곧 진행선), onboarding(상단 진행선 + 카운터), 토스트 자동 닫힘 타이머선, kanban 컬럼 헤더(`4 / 9` 완료 수).
- 진행선이 그라디언트를 쓰는 유일한 UI 신호다. 버튼·배지·카드에는 그라디언트 채움을 금지한다.

## 8. 모션 문법

| 이름 | 값 | 쓰임 |
|---|---|---|
| `--ease-stage` | cubic-bezier(.16, 1, .3, 1) | 장면 진입, 오버레이 등장 |
| `--ease-ui` | cubic-bezier(.2, 0, 0, 1) | hover, 토글 |
| `--dur-ui` | 160ms | hover, 포커스 |
| `--dur-panel` | 320ms | 드로어, 모달, 아코디언 |
| `--dur-scene` | 640ms | 장면 진입 (헤드라인 y 24px→0 + opacity) |
| `--dur-mood` | 900ms | 무드 전환 (등록된 `@property` 색 보간) |
| `--dur-drift` | 10s | 메쉬 제어점 드리프트, alternate 무한 루프 (aurora 8–12s 근거) |

- 장면당 움직임은 메쉬 드리프트 + 진입 1회뿐이다. 글자 쪼개기 애니메이션은 쓰지 않는다.
- index: `scroll-snap-type: y proximity`(≥ 1024px만), ←/→/PageUp/PageDown으로 장면 이동(입력 포커스 중에는 무시), 진행선과 카운터는 IntersectionObserver로 갱신한다.
- 테마 토글: View Transitions API가 있으면 클릭 지점에서 원형 클립 600ms로 "조명 전환", 없으면 즉시 전환.
- `prefers-reduced-motion: reduce`: 드리프트 정지(제어점은 기본 위치), 진입 효과 없음, 무드 전환 즉시, 스냅 해제, 토스트 타이머선은 정적으로 표시. 메쉬 정지 상태가 그대로 완성 화면이 되게 설계한다.
- 화면 밖 무대는 `animation-play-state: paused`로 둔다(IntersectionObserver, 성능).
