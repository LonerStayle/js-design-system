**결론.** v1은 도면에 나오는 **기호를 하나씩 오려 붙인 견본판**이다(모눈, 치수선, 콜아웃, 해치). 실제 도면이라는 **매체**는 만들지 않았다. 실제 도면은 시트 테두리와 구역 표시, 통심선(기둥 중심선) 그리드, 도면 아래에 붙는 도면명, 오른쪽 표제란, 리비전 표, 그리고 감리자가 빨간 펜으로 그린 수정 구름으로 이루어진다. v2는 이 매체를 만든다. 모든 선은 무언가를 재거나, 무언가를 가리키거나, 무언가가 바뀌었음을 알려야 한다.

## 1. 클라이언트 · 세계관

### 스타일의 원래 맥락
- **청사진(시아노타입)**: 1842년 존 허셜이 발명한 철염 감광 인화법이다. 1870년대부터 1940년대까지 건축·기계 도면 복제의 표준이었다. 트레이싱지 원도를 감광지에 겹쳐 햇빛에 노출하면 **프러시안 블루 바탕에 흰 선**이 남는다.
- **디아조 백청사진(화이트프린트)**: 1950년대 이후 청사진을 대체한 방식이다. **흰 종이에 남청색 선**이 나온다. 한국 건축 현장에서는 1990년대까지 "청사진", "청도면"이라고 불렀다. 지금도 현장에서는 출력 도면을 "청도면"이라고 부른다.
- **CAD 도면의 문법**: KS F 1501(건축 제도 통칙)과 ISO 5457·7200의 시트 구성을 따른다. 시트 테두리 + 구역 표시(가로 1~8, 세로 A~F), 통심선(일점쇄선 + 원형 그리드 기호 X1·Y1), 치수선(끝은 화살표가 아니라 45° 사선 틱), 상세 콜아웃(가로로 나뉜 원: 위는 상세 번호, 아래는 시트 번호), 도면명(도면 아래 왼쪽, 굵은 밑줄 + 축척), 표제란(오른쪽 아래 또는 오른쪽 세로 띠)으로 구성된다.
- **레드라인 마크업**: 검토자가 빨간 펜으로 수정할 부분에 구름 모양 테두리(리비전 클라우드)를 그리고, △ 안에 리비전 기호를 쓰고, 손글씨 메모를 단다. 도면 세계에서 "사람이 개입한 흔적"은 이것 하나다.

### 클라이언트 (한국, 가상) — 가선건축사사무소 GSA
- 서울 종로구 서촌에서 소규모 공공건축과 단독주택을 설계하는 사무소다. 2014년 개소했고 직원은 7명이다. 사무소 이름 「가선」은 "가는 선"이라는 뜻이다.
- 2021년부터 협력사(구조·설비·전기)와 발주처, 건설사업관리(CM)사가 함께 도면을 보고 레드라인을 그리고 리비전을 발행하는 웹 도구 **「가선 시트룸」**을 사내에서 만들어 쓴다. 사내 도면 작성 기준집 **「GSA-STD-2026 도면·화면 작성 기준 제2판」**이 CAD 도면과 시트룸 화면에 같이 적용된다. **이 디자인 시스템이 그 기준집의 웹판이다.**
- 지금 진행 중인 대표 프로젝트: **「누하동 작은도서관 신축공사」(NH-2604)**. 종로구가 발주했다. 착공 도면 REV.C 발행을 하루 앞두고 있다.
- 쓰이는 곳:
  1. **작성 기준집 웹판**(index): 신입 직원과 협력사가 선 종류, 문자, 기호, 화면 부재 규격을 확인한다.
  2. **사내 화면**: 발행 현황판(dashboard), 설계질의함(inbox), 도면 작업 보드(kanban), 건축사 프로필(profile), 시트 설정(settings).
  3. **외부 화면**: 신규 프로젝트 개설(onboarding), 설계 용역 요율(pricing), 자체 상품인 소형 목조 모듈 「한칸 HK-3624」 판매(product).
- 왜 이 클라이언트인가: 도면 언어가 장식이 아니라 **업무 언어**로 쓰이는 곳이기 때문이다. 시트룸에서 치수선은 실제 길이를 재고, 리비전 구름은 실제 수정 지시이고, 표제란은 실제로 누가 그리고 누가 승인했는지를 기록한다.

### 감정 톤 (한 문장)
**"발행 전날 오후, 책상 위에 펼친 청도면에서 맞물린 선들이 곧 지어질 건물을 예고하고, 그 위에 빨간 펜 메모 하나가 아직 남아 있다. 차분한 정밀함 속의 기분 좋은 설렘."**
첫 화면 1초 안에 "**정확하다, 사람이 손으로 다듬고 있다, 곧 지어진다**"가 전해져야 한다. 차가운 SF 계기판(시안 네온·모눈), 회색 SaaS 문서, 분양 광고 같은 럭셔리 톤은 금지한다.

## 6. 레이아웃 문법 — 「시트 · 통심선 · 표제란」

이 테마의 화면은 **A1 도면 시트**다. 카드나 섹션이 아니라 시트 위에 **도면(view)을 배치**한다.

1. **시트 프레임**: 페이지 안의 독립 단위는 모두 시트 프레임 안에 놓는다. 바깥 여백은 데스크톱 24px, 모바일 12px이다. 테두리는 바깥 1px `--line-mid` + 6px 간격 + 안쪽 2px `--ink`의 이중선이다. 프레임 바깥 띠에 **구역 표시**를 둔다(위·아래 1–8, 왼쪽·오른쪽 A–F, Plex Mono 11px, 칸마다 틱). 네 변 중앙에는 **중심 표시**(6px 삼각형)를 둔다. 모바일(<600)에서는 위 띠의 1–4만 남긴다.
2. **통심선 그리드**: 시트 안쪽은 12단 CSS 그리드다(gap 0). 2단마다 **통심선 X1–X7**(일점쇄선 `--line-center`, `stroke-dasharray: 18 4 2 4`)을 긋고, 시트 위쪽 가장자리에 **원형 그리드 기호**(지름 28px, 원 안에 `X1`)를 단다. 세로 방향 주요 경계에는 `Y1, Y2…` 기호를 단다. 내용은 반드시 통심선에 맞춰 시작한다. 통심선에서 24px 들어간 위치가 내부 정렬선이다. 그리드 레이어는 navbar의 「통심선」 토글로 끄고 켠다(`data-layer-grid`).
3. **도면명은 아래 왼쪽에**: 섹션 제목은 위 가운데에 두지 않는다. **페이지 이름(h1)도 원칙적으로 첫 시트의 아래 왼쪽 도면명이 맡는다.** 왼쪽 위 거대 제목 + 한 줄 부연으로 시작하는 페이지는 전체에서 1~2개(product 구매 패널의 상품명, dashboard의 카운트다운 판독)만 허용한다. kanban은 시트 번호 띠 + 거르기 줄, inbox는 목록 탭, onboarding은 개설 절차 통심선, pricing은 조건 열 머리 띠로 첫 줄을 시작한다. 각 도면(view) **아래 왼쪽**에 [상세 콜아웃 원(지름 44px, 가로선으로 나눠 위는 상세 번호, 아래는 시트 번호) + 도면명 h2 + 이중 밑줄(2px + 1px, 간격 2px) + 오른쪽 끝에 `S=1:1` 축척]을 둔다. 이것이 이 테마의 유일한 "섹션 헤더"다.
4. **표제란**: 데스크톱(≥1280)에서는 시트 오른쪽 **세로 표제란 띠**(폭 280px)를 둔다. 표지 시트와 장면 페이지에 쓴다. 1279px 이하에서는 시트 아래쪽 **가로 표제란**(높이 auto, 6칸 그리드 → 모바일 2칸)으로 내린다. 표제란 칸 순서는 고정이다: 발주처 / 프로젝트 / 도면명 / 축척·단위 / 작성·검토·승인 / 리비전 표 / 발행일 / **시트 번호(외곽선 거대 숫자)**.
5. **시트마다 다른 구도**: 도면 종류가 구도를 정한다. 평면도는 큰 그림 하나를 시트 2/3에 둔다. 입면도는 가로로 긴 띠를 위아래로 쌓는다. 단면도는 왼쪽에 층 레벨 표시(▽)가 있는 세로 구도다. 상세도는 크기가 다른 상세 여러 개를 서로 다른 축척으로 흩어 배치한다. 일람표는 표를 꽉 채운다. 같은 구도의 시트를 연달아 두지 않는다.
6. **간격 = 치수**: 간격 토큰은 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128px이다. 시트와 시트 사이 간격(데스크톱 96, 모바일 48)에는 **세로 치수선**을 실제로 긋고 값 `96`을 단다. 「치수」 레이어 토글(`data-layer-dims`)로 끌 수 있다.
7. **브레이크포인트**: 360 / 600 / 960 / 1280 / 1440. 시트 최대 폭 1392px(1440 − 24×2). 모바일에서는 통심선이 X1–X4(4단)로 줄어든다.
8. **radius 0.** 원(그리드 기호, 콜아웃, 노드, 아바타, 라디오)만 50%로 둔다. 그림자는 쓰지 않는다. 깊이는 **선 굵기**(1px 일반 → 2px 단면·강조 → 3px 시트 외곽)로만 표현한다.

## 7. 시그니처 (2개, 끝까지)

### 시그니처 ① 「치수선」 — 화면이 자기 크기를 잰다
- 형태: 1px `--ink-2` 치수선이 있고, 양 끝은 **45° 사선 틱**(길이 9px, 화살표 아님)이다. 2px 띄운 보조선이 대상 가장자리까지 내려간다. 값은 선 위 가운데에 Plex Mono 12px로 단다. 값은 **실제 값**만 쓴다(px, mm, ㎡, 장, 일). 장식용 가짜 숫자는 쓰지 않는다.
- 구현: `.dim`(가로) / `.dim--v`(세로) 유틸리티. `::before`(선) + `::after`(틱 2개, `linear-gradient` 대각 1px 또는 SVG mask) + `.dim__value`. 모든 색은 `currentColor`다.
- 적용 위치:
  - index D-501: 2:1 확대한 버튼·입력칸 주위에 높이 44, 좌우 패딩 16, 포커스 링 2+2를 치수 체인으로 표시
  - 시트 사이 간격 96(레이어 토글)
  - 진행률 막대: 위쪽에 0 / 50 / 100 눈금 치수, 현재 값에 지시선
  - 칸반 열 머리: WIP 한도를 치수처럼 `── 4 ──`로 표시
  - 가격 플랜: 요율 계산기 슬라이더 위에 연면적 치수 `240㎡`
  - product: 한칸 입면도 3,600 / 2,400 / 3,150 치수 체인
  - 표: 정렬된 열 머리에 열 폭 틱
  - 툴팁·팝오버: 대상과의 지시선(leader)
  - 404: 사라진 시트의 치수 값을 `?,???`로 둔다(이 경우만 예외)

### 시그니처 ② 「레드라인 리비전 구름 + △」 — 사람이 개입한 곳
- 형태: 대상 주위에 **반원 호가 이어진 구름 테두리**를 그린다(호 반지름 7px, 선 1.5px `--redline`). 구름 오른쪽 위에 **△ 리비전 삼각형**(한 변 22px, 안에 `C` 또는 번호, Plex Mono 11px 500)을 단다. 필요하면 지시선 끝에 **손글씨 메모**(Nanum Brush Script 26px, −3°)를 붙인다.
- 구현: `.cloud` → `::before`에 `mask: url(호 패턴 SVG data URI) repeat` + `background: currentColor`(SVG 속성에 var() 쓰지 않음), `color: var(--redline)`. 그리는 모션은 clip-path를 시계 방향으로 펼친다.
- **의미 규칙**: 구름은 **조치가 필요한 곳**에만 쓴다. 오류 입력칸, 위험 알림, 새 레드라인·미결 RFI, 칸반 카드와 현황판 매트릭스의 「오늘 새 레드라인」 시트(수정 중 자체는 빨간 실선 테두리 + ▲), 설정의 위험 구역, 404의 누락 영역이 여기에 해당한다. 한 화면(뷰포트)에 **최대 2개**까지 둔다. 성공·정보 상태에는 쓰지 않는다. 성공은 `--ok` 실선 사각 도장 `발행 준비`로 표시한다.

### 보조 모티프 (시그니처가 아니라 문법)
통심선 그리드 기호, 상세 콜아웃 원, 레벨 표시 ▽, 45° 해치(진행·막대·선택 면), 축척 바, 방위표(표지에만). 모두 실제 위치·관계를 가리킬 때만 쓴다.

## 8. 모션 문법 — 「플로터가 그린다」

펜 플로터는 선을 일정한 속도로 긋고, 끝에서 멈추고, 튀지 않는다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--ease-plot` | `cubic-bezier(.45, 0, .2, 1)` | 모든 그리기 |
| `--ease-step` | `steps(6, end)` | 숫자 판독, 프린트 |
| `--dur-tick` | 120ms | hover 선 굵기, 토글 |
| `--dur-base` | 240ms | 메뉴·팝오버·탭 밑줄 |
| `--dur-draw` | 700ms | SVG 도면 선 그리기, 구름 그리기 |
| `--stagger` | 50ms(최대 8개) | 도면 선·리스트 행 |

- **등장 = 선 그리기**: `[data-draw]` 안의 SVG path는 `pathLength="1"` + `stroke-dasharray:1; stroke-dashoffset:1→0`으로 그린다. 시트 프레임은 위 → 오른쪽 → 아래 → 왼쪽 순서로 `scaleX/scaleY`가 이어진다(320ms). 그다음 내용이 opacity 0→1(120ms, 이동 없음)로 나타난다. **fade-up과 translateY 등장은 금지한다.**
- **치수선**: 선이 가운데에서 양쪽으로 자라고(240ms), 틱이 찍히고(80ms), 값이 나타난다.
- **숫자 판독**: KPI 숫자는 0에서 목표 값까지 `tabular-nums`로 600ms 동안 CAD 좌표 판독처럼 올라간다(`--ease-step`).
- **hover**: 테두리가 1px → 2px로 두꺼워진다(그림자·lift·색 페이드 없음). 표 행은 `--select` 바탕 + 왼쪽 2px 잉크 바. **press**: 1px 아래로 눌린다(핀 꽂기).
- **오버레이**: 모달은 「상세도 확대」다. 트리거 위치에서 콜아웃 원이 그려지고, 시트가 `clip-path: inset(0 0 100% 0) → inset(0)`(260ms, 플로터 출력처럼 위에서 아래로)으로 나타난다. 드로어는 도면함 서랍처럼 오른쪽에서 `translateX`(240ms, 끝에서 멈춤). 토스트는 위 가장자리에서 출력되듯 펼쳐지고, 닫을 때는 빨간 취소선이 그어진 뒤(160ms) 사라진다.
- **십자선 커서**(index 표지 시트·404 한정, `pointer: fine`일 때만): 뷰포트 전체에 가로·세로 1px `--ink-3` 선을 긋고, 교차점에 도면 좌표 판독 `X 4,812 · Y 2,040`(mm, 평면도 원점 기준)을 단다. `--z-cursor`에 둔다.
- `prefers-reduced-motion: reduce`이면 모든 선을 처음부터 그린 상태로 두고, 숫자는 최종값을 보여 주고, 십자선은 끈다. 오버레이는 즉시 표시한다.

## 13. 카피 원칙
- 화면의 문장은 도면 주기(註記)처럼 쓴다. 명사형으로 짧게, 수치를 넣는다. 예: 「REV.C 발행까지 27시간 40분」, 「열린 레드라인 23건」.
- 형용사 슬로건, 디자인 시스템 자기소개, 「무료로 시작하기 / 데모 보기」는 금지한다.
- 영문은 실제 도면 관례가 있는 표기만 쓴다: `REV`, `SCALE`, `S=1:100`, `NORTH`, `SHEET`, `DWG NO.`, `NONE`, 레이어명. 한 화면에 5개 이하로 쓴다. 나머지는 한국어로 쓴다.
- 인물·날짜·수치는 2절 팩트 시트 값만 쓴다. 「○○」 같은 플레이스홀더는 남기지 않는다.
