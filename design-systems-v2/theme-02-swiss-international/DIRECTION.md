## 1. 클라이언트와 세계관

### 오선음악당 OSEON HALL
- **무엇**: 서울 중구 청계천로의 공공 콘서트홀(가상). 대극장(1,486석)과 실내악홀(412석) 두 홀, 상주 오케스트라 **오선 필하모닉**과 **오선 현악사중주**를 둔다. 매 시즌 공연마다 번호가 붙은 포스터를 한 장씩 찍어 로비 기둥과 청계천 쪽 외벽 게시대에 연속으로 붙인다 — 2026–27 시즌은 41호부터 50호까지. 웹사이트는 공연 예매·시즌권·회원, 그리고 내부 운영(매표 현황, 포스터 제작 보드)을 함께 쓴다.
- **이름의 근거**: 오선(五線) = 악보의 다섯 줄. 수평 헤어라인 다섯 줄이 이 기관의 시그넷이고, 그리드 시스템이 곧 기관의 정체성이라는 서사가 성립한다.
- **이 테마가 진짜 어울리는 이유 (스타일의 원래 맥락)**: 국제 타이포그래피 양식의 대표작은 1950–70년대 요제프 뮐러-브로크만이 만든 **취리히 톤할레(Tonhalle) 연주회 포스터 연작**이다(「musica viva」, 「Beethoven」). 활자와 그리드만으로 음악의 구조를 보여 준 포스터를 시즌마다 번호 매겨 찍었고, 같은 시기 『Neue Grafik』과 『그리드 시스템』이 그 방법을 매뉴얼로 정리했다. 오선음악당은 그 계보를 한국 공공 콘서트홀에 옮긴 클라이언트다 — "스위스풍 SaaS"가 아니라 "그리드로 포스터를 찍는 콘서트홀".
- **감정 톤 (한 문장)**: 개막 전날 밤 로비 기둥에 막 붙은 포스터처럼, 차갑게 계산된 그리드 위에서 거대한 숫자와 활자가 터지는 **정밀한 긴장감**.

## 5. 레이아웃 문법 — "구성 그리드 판(Grid Plate)"

이 테마의 모든 화면은 **판(plate)** 단위로 짠다. 판 = 포스터 한 장. 판끼리는 8px 굵은 룰 또는 판 색 전환으로만 구분하고, 판 안에는 그리드가 실제로 보인다.

1. **그리드**: 데스크톱 12단, 바깥 여백 64px(8×8), 거터 24px. 태블릿(768–1199) 8단, 여백 40px, 거터 24px. 모바일(<768) 4단, 여백 16px, 거터 16px. 베이스라인 8px. 행 모듈 = 96px(데스크톱) / 64px(모바일) — 판 높이와 블록 높이는 모듈 배수.
2. **판 폭은 풀블리드, 내용은 그리드.** 판 배경(흰/잉크/레드)은 뷰포트 끝까지, 그리드는 여백 안에서. `max-width` 중앙 정렬 컨테이너 반복 금지 — 1440을 넘으면 그리드 단이 넓어질 뿐 여백은 64px 고정(최대 1920에서 단 폭 상한).
3. **flush-left, ragged-right 절대.** 가운데 정렬 텍스트 0건. 숫자 표 열만 오른쪽 정렬(단위·자릿수 정렬).
4. **비대칭 스팬만.** 허용 분할: 3/9, 4/8, 5/7, 2/10, 2/5/5, 3/4/5. 금지: 6/6, 4/4/4, 3/3/3/3 균등 카드 그리드. 같은 분할을 연속 두 판에 쓰지 않는다.
5. **빈 단의 의무.** 각 판에 의도적으로 비워 두는 영역이 최소 3단(데스크톱) — 여백이 긴장을 만든다. 단, 칸 높이 불일치로 생긴 우연한 공백은 금지(7-8).
6. **정보 블록은 그리드 교차점에 걸린다.** 텍스트 블록의 위·왼쪽 모서리는 반드시 단 시작선과 모듈 행 시작선에 맞는다. 크롭 디스플레이만 그리드를 무시하고 판 밖으로 나간다(유일한 예외 — 대비가 질서를 증명).
7. **선의 위계 3단.** 8px 판 룰(판 상단, 한 판에 1개) → 2px 블록 룰(블록 제목 위) → 1px 헤어라인(행 구분). 박스 테두리 사방 두르기는 입력·버튼·노출 그리드 판에만.
8. **섹션 제목은 판마다 위치가 다르다.** 왼쪽 위 거대 단어 / 왼쪽 단에 세로쓰기(`writing-mode: vertical-rl`, 한글) / 오른쪽 아래 크롭 / 판 하단 정보 띠 안 — "작은 라벨 → 제목 → 부제" 3단 헤더 반복 금지, "§ 번호 + 제목" 헤더 반복 금지.
9. **모바일**: 4단에서 크롭 숫자는 판 오른쪽으로 잘리고(`overflow: clip`), 정보 블록은 4단 전폭으로 쌓인다. 가로 넘침 0 — 크롭은 판 내부 `overflow: clip`으로만, body 넘침 금지.

## 6. 시그니처

### 시그니처 1 — 노출 그리드 판 (Exposed Grid Plate)
판 배경에 **구성 그리드가 1px 선으로 상시 보인다**: 12단 세로선(`--grid-line`) + 모듈 행 가로선, 판 네 모서리에 인쇄 재단선(crop mark, 길이 16px·간격 8px의 L자 헤어라인, `::before/::after`). 이는 장식이 아니라 "이 포스터가 어떤 격자 위에 짜였는지"의 증명이며, 뮐러-브로크만 『그리드 시스템』 도판 문법이다.
- 구현: `.plate--grid { background-image: repeating-linear-gradient(to right, var(--grid-line) 0 1px, transparent 1px calc((100% - 11*var(--gutter))/12 + var(--gutter))) }` 류 — CSS만, 그라데이션 색 전환 아님(1px 선 반복). 레드/잉크 판 위에서는 `--grid-line-on-plate`.
- 적용 범위: index 모든 판, 각 page의 페이지 헤드 판, 카드(공연 카드 = 미니 포스터: 4×6 모듈선이 보이는 판), 캘린더(날짜 칸 자체가 그리드), 칸반 카드 썸네일, 스켈레톤(로딩 중엔 그리드선만 보이는 빈 판), empty 상태(내용 없는 그리드 판), 좌석 선택 맵, 모달 상단 띠.
- `g` 키 / 그리드 버튼: 페이지 전체에 12단 오버레이(레드 8% 단 면) — v1 기능 유지, 단 기본 노출은 판 안의 선이고 오버레이는 전체 검증용.

### 시그니처 2 — 크롭 디스플레이 (Cropped Display)
**판보다 큰 활자.** 포스터 번호·KPI·날짜를 `--t-poster`(최대 448px) Inter Tight 900으로 세팅해 판의 오른쪽·아래 경계에서 **잘리게** 한다(`overflow: clip`). 잘린 숫자도 읽힌다는 것을 전제로 정한 크기 — 숫자의 최소 60%가 판 안에 남는다. 숫자 중간 줄바꿈 금지(`white-space: nowrap`).
- 적용 범위: index 표지 `26/27`, 포스터 연작 각 판의 `41`–`50`, 페이지 헤드의 포스터 번호(dashboard `76%`의 `76`, kanban 교정 열 카운트 `3`, pricing `8`(「대극장 8」 — 레드 판 안), product `41`, profile `서윤재`, settings `0712`, onboarding 단계 숫자 `1 2 3`, 404 `404`), 진행률(progress)의 거대 퍼센트, steps의 단계 숫자, toast의 대형 시각 없음(작은 컴포넌트엔 축약: 정사각 레드 칸 안의 숫자로).
- 작은 컴포넌트로의 축약형: **레드 정사각 인덱스** — 24/32/48px 정사각 레드 면에 흰 숫자(Inter Tight 900). 배지·탭 번호·스텝·알림 카운트·페이지네이션 현재 쪽. 정사각은 radius 0.

### 공통 재료 (시그니처 아님 — 위계 규칙)
- 오선 시그넷: 수평 헤어라인 5줄(간격 4px, 3px 굵기) + 다섯 번째 줄 끝 레드 정사각 8px. 로고·파비콘·푸터에만.
- 포커스: 2px `--focus` outline + 2px offset — 색이 "움직이는" 유일한 순간.
- 그림자·blur·radius·그라데이션 없음. 떠 있는 레이어(모달·팝오버·메뉴·드로어)는 **1px `--rule` 테두리 + 상단 8px 잉크 룰**로 위계를 표시하고, 배경 딤은 `rgba(11,11,11,.72)` 단색(blur 0).

## 7. 모션 문법 — "선이 그어지고, 판이 놓인다"

요소는 **움직이지 않는다**(translate·scale·bounce 금지). 변하는 것은 선의 길이와 색뿐.

| 이름 | 대상 | 값 |
|---|---|---|
| `rule-draw` (주 모션) | 판 룰 8px·블록 룰 2px·탭 밑줄·진행 바·불릿 차트 막대 | `transform: scaleX(0→1)`, `transform-origin: left`, **480ms `cubic-bezier(.2,0,0,1)`**, 뷰포트 진입 시 1회(IntersectionObserver, threshold .3), 같은 판 안 순차 지연 60ms·최대 6개 |
| `grid-set` (판 등장) | 노출 그리드선 | 그리드선 opacity 0→1 240ms 후 내용은 즉시 표시(내용은 페이드하지 않음) |
| `ink-shift` (hover) | 링크·버튼·행 | 색 전환 120ms `linear` — 링크는 밑줄 2px 레드 `rule-draw` 축소판(180ms), 버튼은 면 `#DA291C→#B81E14`, 표 행은 `--surface-2` |
| `tab-rule` | 탭·세그먼트 선택 표시 | 2px 레드 밑줄이 새 탭 폭·위치로 240ms 이동(`left`/`width` 대신 `transform`+`scaleX`) — 유일한 수평 이동, 선이므로 허용 |
| `plate-cut` (오버레이) | 모달·드로어·커맨드 팔레트 | 이동 없음. 딤 opacity 0→1 160ms, 패널은 즉시 등장 + 상단 8px 룰 `rule-draw` 320ms |
| `marquee` | 로비 전광판 띠 | 선형 40s 무한, hover·focus 시 정지, 일시정지 버튼 |
| `spinner` | 로딩 | 정사각 4칸 중 1칸 레드가 시계방향으로 이동(steps(4), 800ms) — 원형 스피너 없음 |

rule-draw 는 **점진적 향상**(수정 2차): CSS 기본값은 그려진 상태. app.js 가 `html.js-motion` 을 붙이고 로드 시점에 뷰포트 아래에 있던 장식 선(판 룰 등)만 대기시킨다. **데이터 막대(불릿·일별 막대)는 한 번도 숨기지 않는다** — 들어올 때 WAAPI 로 한 번 그어질 뿐. 인쇄·IO 미지원·감속 모션에서는 전부 그려진 상태.

- 화면당 모션 장치 최대 2개(ux 근거): 기본은 rule-draw + ink-shift.
- `prefers-reduced-motion: reduce` → 모든 선은 그려진 상태, 그리드선 즉시 표시, 마퀴 정지(정적 목록으로), 스피너는 정지 + "불러오는 중" 텍스트, 탭 밑줄 즉시 이동.
- 토큰: `--dur-1: 120ms; --dur-2: 240ms; --dur-3: 480ms; --ease-rule: cubic-bezier(.2,0,0,1); --ease-linear: linear;`
